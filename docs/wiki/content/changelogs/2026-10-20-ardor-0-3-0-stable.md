# Changelog - 2026-10-20

## ARDOR 0.3.0 is stable

<Badge type="tip" text="Enhancement" />

**In one line.** All four ARDOR packages are published at 0.3.0 on `latest`, built on IGNIS 0.3.0, and ARDOR and IGNIS share a minor version from now on.

```bash
bun add @venizia/ardor
```

## What changed

- **One version for the four packages.**

| Package | Version | IGNIS peers |
|---------|---------|-------------|
| `@venizia/ardor` | 0.3.0 | `^0.3.0`: `ignis-kernel`, `ignis-helpers`, `ignis-inversion`, `ignis-filter`, `ignis-connectors` (optional) |
| `@venizia/ardor-kernel` | 0.3.0 | `^0.3.0`: the same five, `ignis-connectors` optional |
| `@venizia/ardor-react`, `@venizia/ardor-admin` | 0.3.0 | `^0.3.0`: `ignis-kernel`, `ignis-helpers`, `ignis-inversion`, `ignis-filter` |

- **ARDOR and IGNIS share a minor.** ARDOR 0.3.x pairs with IGNIS 0.3.x, so the version goes from 0.1.5 to 0.3.0 and skips 0.2. Patches move independently on each side. `@venizia/vulcan` and `@venizia/dev-configs` keep their own version lines.
- **The code is the code of 0.1.5.** The source of the four packages did not change between 0.1.5 and 0.3.0. What changed in the packages is their manifests, which carry the new IGNIS peer ranges.
- **A project preset.** `vulcan init --preset ardor` creates a monorepo with a working admin, and `vulcan add --preset ardor` adds one to a monorepo that exists (VULCAN 0.3.0 or newer). See [ARDOR ships a VULCAN preset](./2026-10-20-vulcan-preset) and [Create a project](../guides/get-started/create-a-project).
- **A package can be released at an explicit version.** This is release tooling and changes nothing for an application.

## Who is affected

- **An application on ARDOR 0.1.x.** Move the four ARDOR packages and every `@venizia/ignis-*` package to 0.3.0 in one change. A `^0.2.2` IGNIS range does not match 0.3.0, so a package left behind installs a second copy of its siblings.
- **A library that peers on ARDOR or IGNIS.** Move its peer ranges with them.
- **A new project.** Start from the preset.
