---
title: 0.4.8
version: 0.4.8
packages: ['@venizia/ardor-kernel', '@venizia/ardor-react', '@venizia/ardor-admin', '@venizia/ardor']
---
ARDOR 0.4.8 adds a set of browser hooks and helpers (media query, visibility, online status, intersection, resize, clipboard, storage listing and a plain-text codec), a default token refresh, and an application id that keeps two apps on one origin apart. It also drops `lodash`, removes `useSizer`, `AnyType`, `AnyObject`, two aliases and the HTTP repository's `updateAll` and `deleteAll`, renames one hook, makes sign-out clear the user's stored data and query cache, remembers the chosen language, fills the gaps of a partial language with English and checks feature messages of every language at start, and moves the packages to the IGNIS 0.4.8 line.

## Breaking
- **useSizer is removed** `remove-use-sizer` (`@venizia/ardor-react`, `@venizia/ardor`): `useSizer`, `IUseSizerOptions` and `IUseSizerReturn` are gone, with no alias. Call `useElementSize({ ref, box: 'border-box', round: true })` and give the element a `ref` instead of an id. The size is close to what `useSizer` read, not identical, and the hook also returns `measured`.
- **useInjectableContainer is now useApplicationContainer** `rename-use-injectable-container` (`@venizia/ardor-react`, `@venizia/ardor`): same behaviour, new name, no alias. The error text now reads `[useApplicationContainer] Failed to determine the application container!`. Replace the name in your code.
- **ISendResponse is removed** `remove-send-response` (`@venizia/ardor-kernel`, `@venizia/ardor-admin`, `@venizia/ardor`): use `INetworkResponse`, the same type. `ardor codemod namespace --write` renames it.
- **IListFilter.offset is removed** `remove-list-filter-offset` (`@venizia/ardor-admin`, `@venizia/ardor`): use `skip`, the field the list filter builder sets. Nothing in ARDOR read `offset`.
- **HttpRepository loses updateAll and deleteAll** `remove-http-repository-update-all-delete-all` (`@venizia/ardor-kernel`, `@venizia/ardor`): the HTTP repository re-exported from the `repository` entry no longer has them. Call `updateBy` and `deleteBy`, which take the same options, except that `deleteBy` now requires `where` (it was optional, and a call without it failed at run time).
- **lodash is no longer installed** `drop-lodash` (`@venizia/ardor-react`, `@venizia/ardor-admin`): the packages no longer depend on `lodash`; add it to your own `package.json` if you import it. A selector from `SelectorHooks.create().useDeepEqualSelector` that returns a `Map`, a `Set` or a class instance now compares by identity, and in message sources (`DefaultI18nProvider.composeMessages`) an array in a later source replaces the earlier one.
- **A refreshTokenPath now refreshes the token** `default-token-refresh` (`@venizia/ardor-kernel`, `@venizia/ardor-admin`, `@venizia/ardor`): with `authRecovery.refreshTokenPath` set and the auth service bound, a `401` sends a POST with no body to that path, saves the token of the answer and retries the request once. If the path is not a refresh endpoint, remove the setting or override `refreshToken`. A subclass that only posted to the path and saved the token can be deleted. A subclass that overrides `DefaultRestDataProvider.createNetworkService()` passes the new `authService` option on to `DefaultNetworkRequestService`, or the refresh and the id-scoped token read do not work.
- **Sign-out removes the stored data and the query cache** `sign-out-clears-store` (`@venizia/ardor-admin`, `@venizia/ardor`): when the session ends, every key under `@app/store/` (or `@app/store/<id>/`) in `localStorage` and `sessionStorage` is removed and the query client is emptied. A preference that must outlive sign-out moves to a key outside that prefix, such as `@app/prefs/<name>`, or you override `clearStoredData`. The old key is not migrated.
- **AnyType and AnyObject are removed** `remove-any-aliases` (`@venizia/ardor-kernel`, `@venizia/ardor`): the two names are no longer exported, as IGNIS removed them. Use `unknown`, a named type or `Record<string, unknown>`; an `interface` value does not fit `Record<string, unknown>`, so spread it, type it as `object`, or declare it as a `type` alias.
- **The list params carry unknown, not any** `typed-list-params` (`@venizia/ardor-kernel`, `@venizia/ardor-admin`, `@venizia/ardor`): `ICustomParams` has an index signature of `unknown`; an override of `getList` or `getManyReference` that passes react-admin's params to `super` spreads them (`{ ...params }`). `getOne` and `getMany` need no change.
- **The query of doRequest is typed** `typed-do-request-query` (`@venizia/ardor-kernel`, `@venizia/ardor`): `DefaultNetworkRequestService.doRequest({ query })` is `Record<string, unknown>`, not `any`. An object literal fits; an `interface` value does not, so spread it.
- **The stored user is typed** `typed-stored-user` (`@venizia/ardor-kernel`, `@venizia/ardor-admin`, `@venizia/ardor`): `DefaultAuthService.getUser()` and the `user` of `onSessionStarted` are `IAuthUser`, not `any`; a field you added yourself is not on the type until you check it with `in`. A stored identity with a wrong field type reads as empty, and `getIdentity` resolves an `id` equal to the `userId`.
- **An override of getUser must fit IAuthUser** `typed-user-override` (`@venizia/ardor-kernel`): an override of `getUser`, or a stub of the auth service, returns fields that fit `IAuthUser`; extra fields and an `interface` of your own are fine.
- **The user id is a string or a number** `typed-user-id` (`@venizia/ardor-kernel`, `@venizia/ardor-admin`): `getUser().userId` and the `id` of `getIdentity()` are `IdType`, and the user id is absent when nothing is stored, so a function that takes a `string` needs the value converted.
- **The codemod refuses to write outside a git repository** `codemod-safe-write` (`@venizia/ardor`): `ardor codemod namespace --write` now refuses (exit 1) in a folder that is not a git repository, where nothing can undo a write, unless you add `--allow-dirty`; a CI step on an exported tree needs that flag. It also rewrites in memory first and writes only if every file went through, and inside a repository it still refuses a file with local changes.
- **The IGNIS peers are higher** `ignis-peers` (`@venizia/ardor-kernel`, `@venizia/ardor-react`, `@venizia/ardor-admin`, `@venizia/ardor`): the packages now require `@venizia/ignis-kernel` and `@venizia/ignis-connectors` `^0.4.8-16`, `@venizia/ignis-helpers` and `@venizia/ignis-boot` `^0.4.8-14`, `@venizia/ignis-inversion` `^0.4.7-5` and `@venizia/ignis-filter` `^0.4.7-6`; `@venizia/ignis-boot` and `@venizia/ignis-connectors` stay optional peers. Install the IGNIS versions first.
- **A stereotype's when is honoured** `stereotype-when-honoured` (`@venizia/ardor-kernel`, `@venizia/ardor`): a class whose `when` returns `false` is no longer bound, and neither are its `@provide` methods. Before, `@service({ when })` and the same option of the other stereotypes were ignored and the class was always bound. `when` runs once with `{ application }` and must return a boolean at once: a promise, another value or a throw stops `start()` with an error that names the class. A class you register by hand with `service(X)` is bound whatever its `when` says. `order` and `after` are still not read.
- **A duplicate key throws, and bindingList respects allowOverride false** `duplicate-explicit-key-throws` (`@venizia/ardor-kernel`, `@venizia/ardor`): two different classes that pin the same key with `binding: { namespace, key }` (or one pins the key the other derives from its name) now stop `start()` with an error that names both classes and the key; before, the class imported last won in silence. A `bindingList()` entry, or a discovered class, under a key held by a class declared `allowOverride: false` now throws too; before, it replaced the class. `bindContext()` still replaces anything, on purpose.
- **Sign-in is an explicit toggle** `auth-provider-toggle` (`@venizia/ardor-kernel`, `@venizia/ardor-admin`, `@venizia/ardor`): `CoreBindings.AUTH_PROVIDER_OPTIONS` is now `{ use: true, paths? }` or `{ use: false }` (`TAuthProviderOptions`), and unbound means `{ use: false }`. The auth provider is used only with `use: true`. An app that still binds `{ paths }` without `use` fails at the start with an error that names the key and says to add `use: true`; it no longer runs with every page public. An app that binds an auth provider of its own under `DEFAULT_AUTH_PROVIDER` and no options fails at the start the same way, naming both keys: it must bind `{ use: true, ...paths }` to use the provider, or `{ use: false }`. `isAuthRequired: true` with sign-in off throws. A `DefaultAuthProvider` subclass whose constructor takes the options types them as `TAuthProviderOptions`. `ardor codemod auth-options --write` adds `use: true` to an options object literal and lists options that are not one.
- **BaseArdorApplication moved to the admin package** `base-application-moved` (`@venizia/ardor-kernel`, `@venizia/ardor-admin`): import it from `@venizia/ardor-admin` instead of `@venizia/ardor-kernel`. An import from `@venizia/ardor` does not change. The kernel keeps `AbstractArdorApplication`. `ardor codemod base-application-import --write` changes the import.
- **injectable() is removed** `injectable-removed` (`@venizia/ardor-kernel`, `@venizia/ardor`): the application method `injectable(scope, value, tags)` is gone, and `IArdorApplication` now has the same signatures as the class. Register with `service()`, `repository()`, `dataSource()` or `component()` (each takes `{ binding, scope }` and returns the binding), or list the class in `bindingList()`. The `@injectable` decorator is unchanged.
- **start() rejects a blank application name** `boot-validates-configuration` (`@venizia/ardor-kernel`, `@venizia/ardor-admin`, `@venizia/ardor`): `start()` now fails when `getAppInfo()` returns an empty or blank `name`, or a `version` that is not a string; an app that started with an empty name now fails at `start()`, so give it a name. The `id` is checked there too: an `id` with anything but letters, digits, `.`, `_` and `-` fails at `start()`, no longer at the first render. An application whose providers cannot be built (for example no `REST_DATA_PROVIDER_OPTIONS`) now fails at `start()` too, with an error that names the key to bind.
- **RuntimeConfig.get has no required option** `runtime-config-get-required` (`@venizia/ardor-kernel`, `@venizia/ardor`): `get({ key, required: true })` is gone; call `RuntimeConfig.getRequired({ key })`, which returns a `string`, takes no `defaultValue` and throws the same coded error (`RUNTIME_CONFIG_REQUIRED_CODE`, the key in `extra.key`) when the value is unset. A `required: true` next to a `defaultValue` never did anything: delete one of the two.
- **A key two features define stops the app at start** `feature-key-collision-at-startup` (`@venizia/ardor-admin`, `@venizia/ardor`): two features that give the same message key in a language whose messages they bundle (not loaded lazily) now make the i18n provider throw when it is built, naming both features. A collision between lazy bundles cannot be seen then: `assertArdorApplicationBoots` loads every language the app offers (and the fallback language) and fails on it, and at run time it is logged when a user switches to that language, and the switch goes ahead. Before, the error showed only when a user switched to that language, and the app started fine in the others. Give each feature its own keys, or relabel the key in the application's own `i18nSources`.
- **Hooks check the class a key is bound to** `hooks-check-the-bound-class` (`@venizia/ardor-react`, `@venizia/ardor`): two classes with the same name share one binding key, and `useInjectable({ target })` and the `useService`, `useRepository`, `useProvider`, `useComponent` and `useConfiguration` hooks returned an instance of the other class. They now throw and name the key and the class when the bound class is not the one you passed. A subclass bound under the key of its parent is accepted, and a value or provider binding has no class to compare. Give one of the two classes its own key with `binding: { namespace, key }`. The same check applies when you bind another class under the key of a stereotyped class to replace it (an override or a test fake): make that class extend the one it replaces, or bind a value, or the hook throws. This is a break for such an override or fake that does not extend the class it replaces.
- **The first language is chosen better** `initial-locale-detection` (`@venizia/ardor-admin`, `@venizia/ardor`): the app now starts in the stored language, else the first of the browser's languages that the app offers, matched as a full tag (`pt-BR`) and then as its main part (`pt`), else the first language in `languages`. Before, the main part of the first browser language was compared and `en` was used when it did not match. An app whose `languages` does not start with `en` and whose visitor's language is not offered now starts in its own first language instead of English (`fr-FR` against `['vi', 'en']` gives `vi`), and so does a run with no `navigator`. `pt-BR` and `zh-TW` in `languages` now match.
- **The boot test checks every language** `boot-test-every-locale` (`@venizia/ardor-admin`, `@venizia/ardor`): `assertArdorApplicationBoots` now loads the features' messages of every language the app offers, not the first one only, and does not switch the provider's language. A feature loader that fails, or a key two features define, in any language now fails the test, so a boot test that passed before can fail now. The test blocks `fetch`, so a loader that downloads its catalogue fails for every language; `locale` limits the check to one language, for a loader that does not. `Features.verifyMessages({ features, locales })` is the new helper behind it.

## Added
- **ardor codemod --list** `codemod-list` (`@venizia/ardor`): `ardor codemod --list` prints the name of each codemod, one per line, and exits 0. A tool can check a name with it before it runs `ardor codemod <name>`.
- **Three more codemods** `codemods-wave-2` (`@venizia/ardor`): `ardor codemod` now has `auth-options`, which adds `use: true` to the auth provider options of an app with sign-in, `base-application-import`, which imports `BaseArdorApplication` from `@venizia/ardor-admin`, and `default-providers`, which only lists the default providers an app builds by hand and never writes. They take the same flags as `namespace` (`--write`, `--check`, `--allow-dirty`) and refuse a file with local changes the same way; `default-providers` refuses `--write` with exit code 2.
- **Application id** `application-id-keys` (`@venizia/ardor-kernel`, `@venizia/ardor-admin`, `@venizia/ardor`): `IApplicationInfo.id` scopes the session and store keys, so two apps on one origin no longer share a session or sweep each other's data at sign-out. `LocalStorageKeys.scoped({ id })` and `DefaultAuthService.keys` give the keys, and `DefaultNetworkRequestService.createAuthTokenReader({ id })` reads the matching token; `LocalStorageKeys.scoped` returns `IScopedKeys`, and `AuthTokenStore.read` and `write` take an optional `{ key }`. A `DefaultAuthService` subclass with its own constructor passes the application info to `super(info)` when an id is set: otherwise `DefaultAuthProvider.value()` throws at boot. Without an id nothing changes; with one, users sign in once under the new keys and the old keys stay on disk.
- **useMediaQuery, useDocumentVisibility and useOnlineStatus** `browser-state-hooks` (`@venizia/ardor-react`, `@venizia/ardor`): three server-render-safe hooks that re-render when the browser state changes. They join the `Ardor` namespace.
- **useIntersection** `use-intersection` (`@venizia/ardor-react`, `@venizia/ardor`): returns the latest `IntersectionObserverEntry` of a target. `target` can also be a list (the result is a list in the same order), `root` names a scroll container and `threshold` can be a list of numbers.
- **useResizeEffect** `use-resize-effect` (`@venizia/ardor-react`, `@venizia/ardor`): calls one callback when any of several elements, or their direct children, resize, at most once per frame, or before paint with `beforePaint`. `useElementSize` uses the same observing helper, each hook with its own observer. `IUseResizeEffectOptions`, `IUseIntersectionOptions` and `TElementTarget` are new types.
- **useUntypedTranslate** `use-untyped-translate` (`@venizia/ardor-admin`, `@venizia/ardor`): `translate(key: string)` for keys known only at run time. `useTranslate` stays typed. `TUseUntypedTranslateFn` is the new type.
- **BrowserClipboard** `browser-clipboard` (`@venizia/ardor-kernel`, `@venizia/ardor-react`, `@venizia/ardor`): `writeText({ text })` and `readText()` work outside React and answer `false` or `undefined` instead of throwing. `useCopyToClipboard` uses it, so it no longer throws where `navigator` is missing, and it now takes `{ resetMs }` (`IUseCopyToClipboardOptions`) and returns `{ copy, isCopied }`.
- **BrowserStorage.keys and removeWhere** `browser-storage-keys` (`@venizia/ardor-kernel`, `@venizia/ardor`): list the keys of an area by prefix and remove the keys under a prefix. `removeWhere` needs a `prefix`, and an empty one removes nothing; `keys` takes an optional `prefix` and lists every key without one, and the session keys under `@app/auth/` are never removed.
- **Storage subscribers know where a change came from** `storage-subscribe-is-external` (`@venizia/ardor-kernel`, `@venizia/ardor`): the listener of `BrowserStorage.subscribe` receives `{ isExternal }` (`IStorageChange`), `true` for a change made in another tab. A listener that takes no argument keeps working.
- **StorageCodecs.text** `storage-text-codec` (`@venizia/ardor-kernel`, `@venizia/ardor-react`, `@venizia/ardor`): a codec for a key that holds a bare string, with an optional `allowed` list that types the value and refuses others. With a `codec`, `BrowserStorage.get` accepts a fallback of another type, and `set` and `useStoredState` check the value against the codec's type instead of widening it (compile time only).
- **useStoredState writeDelayMs and a null key** `stored-state-options` (`@venizia/ardor-react`, `@venizia/ardor`): `writeDelayMs` changes `value` at once and writes the storage once after the last `setValue`, and writes a pending value on unmount, a new key, `pagehide` or a hidden tab. `key: null` keeps the value in memory like `useState` and stores nothing. `IUseStoredState` types the two overloads.
- **Sign-in can stay on the page** `after-login-false` (`@venizia/ardor-kernel`, `@venizia/ardor-admin`, `@venizia/ardor`): `paths.afterLogin: false` makes `login` resolve with `redirectTo: false`, and `ApplicationProviders.resolve({ container, isAuthRequired: true })` types `authProvider` as present.
- **reduxStore is optional** `redux-store-optional` (`@venizia/ardor-admin`, `@venizia/ardor`): `ArdorApplication` mounts no Redux provider without a store. `useAppSelector` and `useAppDispatch` need one.
- **A route can need permission** `feature-route-access` (`@venizia/ardor-admin`, `@venizia/ardor`): a route of a feature, or of the `routes` prop of `ArdorApplication`, can declare `access: { resource, action }` (`TArdorRoute`, `IRouteAccess`). It then renders only for a signed-in user whom the `canAccess` of the permission provider allows; before, react-admin checked neither on a custom route, so a page was open to anyone who typed its path. A route with `access` fails at mount, naming the route, when nothing could answer it: sign-in is off (react-admin treats that as everyone signed in) or no permission provider is bound (the auth provider then has no `canAccess` and lets every signed-in user pass). A route without `access` behaves as before, open unless `requireAuth` is set.
- **Test fakes** `test-fakes` (`@venizia/ardor-kernel`, `@venizia/ardor`): `FakeIntersectionObserver`, `FakeMatchMedia`, `FakeStorage` and `FakeClipboard` join `FakeResizeObserver`, which now shows its observers. They come from `@venizia/ardor/testing` and from the new `@venizia/ardor-kernel/testing`.
- **useProvider and useInjectable type the provider keys** `use-provider-typed-key` (`@venizia/ardor-react`, `@venizia/ardor-admin`, `@venizia/ardor`): `useProvider({ key: CoreBindings.DEFAULT_REST_DATA_PROVIDER })` returns `IDataProvider`, `DEFAULT_AUTH_PROVIDER` returns `IAuthProvider` and `DEFAULT_I18N_PROVIDER` returns react-admin's `I18nProvider`, with no generic and no augmentation in your app; `useInjectable({ key })` does the same. `IUseInjectableKeyTypes` is the new interface that maps a key to its type: add your own keys to it with `declare module '@venizia/ardor'`, and a key you add there is valid and typed. A key that is listed nowhere still fails to compile. `useProvider({ target })` is unchanged. A generic you pass with a key (`useProvider<IDataProvider>({ key })`) still compiles and is your claim: it is not checked against the mapped type. `IUseInjectableByTarget` and `IUseInjectableByKey` are the new option types.
- **useInjectable infers the type of a target** `use-injectable-infers-target` (`@venizia/ardor-react`, `@venizia/ardor`): `useInjectable({ target: PricingService })` returns a `PricingService`, as `useService` does, where it returned `unknown` before. A generic you pass with a target is still accepted and is not checked against the class, so leave it out.
- **The chosen language is remembered** `locale-persisted` (`@venizia/ardor-kernel`, `@venizia/ardor-admin`, `@venizia/ardor`): the language a user picks is stored in `localStorage` and read first on the next visit, so a reload keeps it, and a sign-out does not remove it. It is on by default; `locale: { persist: { use: false } }` in the i18n options turns it off. A stored language the app does not offer is ignored. `LocalStorageKeys.PREFIX_PREFS` (`@app/prefs/`) names the prefix for such preferences, and `LocalStorageKeys.scoped({ id })` returns `prefsPrefix` and `locale` next to the other keys.
- **A missing message is logged** `i18n-missing-key-log` (`@venizia/ardor-admin`, `@venizia/ardor`): when a key has no text in any layer, the screen still shows the key, and the i18n provider now logs one warning for that key and language, so a typo or an untranslated text can be found.
- **THttpFetch** `http-fetch-type` (`@venizia/ardor-kernel`, `@venizia/ardor`): the `repository` entry exports the type of the `fetch` setting of `HttpDataSource`, so requests can go through a test double or a proxy. Without it the platform `fetch` is used.
- **ARDOR binds the default providers** `default-providers-bound` (`@venizia/ardor-kernel`, `@venizia/ardor-admin`, `@venizia/ardor`): `BaseArdorApplication` binds `DefaultRestDataProvider`, `DefaultAuthService`, `DefaultAuthProvider` and `DefaultI18nProvider` itself, so an app binds only their options. `DefaultAuthService` is always bound, so a guest app's data provider also reads its tokens through it (under the id-scoped keys when `IApplicationInfo.id` is set), and an `authRecovery.refreshTokenPath` now refreshes. A minimal app binds `REST_DATA_PROVIDER_OPTIONS`; `I18N_PROVIDER_OPTIONS` is optional (unbound means English only). To replace a default, bind its key in `bindContext()` with one line, `.toProvider(CountRestDataProvider)`; a `@provide` method or `bindingList()` also wins. Code that builds the providers itself keeps working; `ardor codemod default-providers` lists those places. `AbstractArdorApplication.bindDefaults()` is the new hook that binds them.
- **Option keys are type-checked** `typed-option-keys` (`@venizia/ardor-kernel`, `@venizia/ardor-admin`, `@venizia/ardor`): `@provideOption({ key })` is `@provide` for the `*_OPTIONS` keys of `CoreBindings`, and the compiler checks that the method returns the options type of its key (`ICoreOptionTypes`), so a wrong return type fails in your editor and not during a render. `@provide` with the same keys still works but is not checked.
- **ApplicationProviders.assertConfigured** `assert-configured` (`@venizia/ardor-admin`, `@venizia/ardor`): `ApplicationProviders.assertConfigured({ container })` resolves the data, auth and i18n providers at once and throws an error that names the missing binding key and says what to bind. `BaseArdorApplication.postConfigure()` calls it, so a missing options binding, or auth options without the `use` toggle, rejects `start()` and not the first render. A subclass that overrides `postConfigure()` calls `super.postConfigure()` first.
- **RuntimeConfig reads numbers and booleans** `runtime-config-transform` (`@venizia/ardor-kernel`, `@venizia/ardor`): `get` and `getRequired` take a `transform` that turns the value into a number, a boolean or another type, and `get` with a `defaultValue` returns a `string`. A `transform` that throws, or that answers nothing to `getRequired`, raises an error with the new code `RUNTIME_CONFIG_INVALID_CODE` and the key in `extra.key`, never the value.
- **RolePermissionProvider** `role-permission-provider` (`@venizia/ardor-kernel`, `@venizia/ardor`): an optional permission provider for apps that keep a table of roles and what each role may do. Bind it with `this.bind({ key: CoreBindings.PERMISSION_PROVIDER }).toClass(RolePermissionProvider)` and return `{ grants }` from a `@provideOption({ key: CoreBindings.PERMISSION_PROVIDER_OPTIONS })` method. A grant is `'orders.edit'`, `'orders.*'`, `'*.list'` or `'*'`; a user may do what any of their roles grants, and a user with no roles, or no one signed in, may do nothing. `IRolePermissionProviderOptions` is the new type. ARDOR still binds no permission provider by itself, and an app with other needs binds its own `IPermissionProvider`.
- **useRoles** `use-roles` (`@venizia/ardor-admin`, `@venizia/ardor`): returns the roles of the signed-in user as a `ReadonlySet<string>` and re-renders when the session changes, also when it changes in another tab. The set is empty when nobody is signed in or no auth service is bound. It joins the `Ardor` namespace.

## Changed
- **No source maps in the packages** `no-source-maps` (`@venizia/ardor-kernel`, `@venizia/ardor-react`, `@venizia/ardor-admin`, `@venizia/ardor`): `.map` files are no longer published, so a tool that reads them from `node_modules` finds none and stack traces point into `dist`.
- **The preset has no catch-all vendor chunk** `preset-vendor-group` (`@venizia/ardor`): a new app's `vite.config` keeps only the `react` code-splitting group, so libraries used by a lazy route no longer load on the first screen. An existing app keeps its own config and can remove its `vendor` group.
- **A blank runtime value is unset** `runtime-config-blank-is-unset` (`@venizia/ardor-kernel`, `@venizia/ardor`): `RuntimeConfig.get` treats a value made only of spaces as unset, as it already did for an empty one, in `window.__APP_CONFIG__` and in the build-time env, so `defaultValue` or the next source applies instead of `"   "`.
- **English fills the gaps of every language** `i18n-english-fallback` (`@venizia/ardor-admin`, `@venizia/ardor`): a catalogue that translates only some keys no longer shows the others as raw keys. ARDOR's English texts are always the bottom layer, then the features' and the application's English, then the chosen language, so `ra.action.save` reads `Save` in a partial `vi` and a feature that ships only `en` shows its English texts in every language. `fallback: { locale }` in the i18n options picks another bottom language. This is not breaking: an application that spreads `englishMessages` into its catalogues still works, and the spread is no longer needed.
- **A new app binds only its options** `scaffold-binds-options-only` (`@venizia/ardor`): the app the preset creates, and the examples, bind the options of the REST data provider and of sign-in with `@provideOption`, not the providers: the base application binds those. An existing app is not changed.

## Fixed
- **A feature's lazy messages are read as messages** `feature-loader-unwrap` (`@venizia/ardor-admin`, `@venizia/ardor`): a feature with `vi: () => import('./vi')` now shows its texts. Before, every key of that feature read as the raw key, because the module was taken for the messages. A loader may resolve to the messages or to a module whose default export is the messages, as an application's own source already could.
- **useStoredState updaters compose** `stored-state-chained-updaters` (`@venizia/ardor-react`, `@venizia/ardor`): `setValue((previous) => ...)` now runs on the value at the moment of the call, so two updaters in one tick both apply. In StrictMode in development an effect that increments runs twice, as with React's `setState`.
- **useRefreshToken refreshes the permission checks** `refresh-token-invalidates-can-access` (`@venizia/ardor-admin`, `@venizia/ardor`): after a refresh, `useRefreshToken` invalidates the cached `canAccess` answers, the queries that permission checks use. It invalidated `getPermissions`, which the default auth provider always resolves with `undefined`, so a refresh changed nothing.
- **build-info.json is refreshed on each rebuild** `build-info-refreshed-on-rebuild` (`@venizia/ardor`): under `vite build --watch`, each rebuild now writes its own commit and `builtAt` in `build-info.json`, where every rebuild used to repeat the first one.
- **A failed language switch no longer splits the app** `i18n-failed-switch` (`@venizia/ardor-admin`, `@venizia/ardor`): when a feature's lazy messages fail to load, the switch used to reject, so the language menu, `<html lang>` and the `x-locale` header said the new language while the screen kept the old one. Now the failure is logged, the screen shows the fallback messages in the new language, and the next switch tries the loader again.
- **A lazy messages loader runs once at a time** `i18n-loader-single-call` (`@venizia/ardor-admin`, `@venizia/ardor`): two language switches made before a loader (an application source or a feature's) finished used to call it twice. They now share one call, and a call that failed is forgotten so the next switch tries again.

## Security
- **Run the codemod with `bun run ardor`** `codemod-commands-no-install` (`@venizia/ardor`): `bunx`, `bun x` and `npx` with the bare name `ardor` fetch an unrelated package of that name from npm when the bin is not installed, so a consumer who ran it from the root of a monorepo ran someone else's code. `--no-install` stops the fetch but still runs a copy that an earlier fetch left in the runner cache. Change your own scripts, CI and docs to `bun run ardor ...` inside the package that depends on `@venizia/ardor`, and delete the cached copies: `rm -rf ~/.bun/install/cache/.bunx-*/ardor@* ~/.bun/install/cache/.bunx-*/devz@* ~/.bun/install/cache/.bunx-*/vulcan@* ~/.bun/install/cache/.bunx-*/vulcan-atlas@*`. The docs and the `ardor` help say so now, and the IGNIS codemod runs as `bun run devz codemod ...` inside the package that depends on `@venizia/dev-configs`. `vulcan migrate apply` does not fetch anything: it runs only a bin found in `node_modules/.bin` that resolves inside an installed package of the source, and leaves the step manual otherwise.
- **A late 401 no longer reaches the next user's session** `late-401-keeps-new-session` (`@venizia/ardor-kernel`, `@venizia/ardor-admin`, `@venizia/ardor`): a request sent by a user who has since signed out, answered `401` after another user signed in, no longer refreshes the new session, replays the first user's request with the new user's token, or signs the new user out. `doRequest` and a repository call through `getDataSourceAuth()` reject it with a `401` whose code is `SESSION_CHANGED_CODE`, and `DefaultAuthProvider.checkError` resolves for that code. `doRequest` checks again after the refresh and after the retry, and a repository call after the refresh. A refresh that fails and ends the session itself leaves the `401` as it is, so the app still goes to sign-in. The refresh is shared only by the requests of one session. An override of `checkError` that reads only the status should skip it too. If the same user holds another token by then (a new sign-in or another tab), the request is retried with that token and nothing is refreshed. A service with no auth service cannot tell who is signed in, so another token there is a session change, not a refresh to retry with, unless its own `refreshToken` saved it. `DefaultAuthService.saveAuth` writes the identity and the roles before the token, so a tab that reads in between never pairs one user's identity with another's token, and `checkAuth` follows the session signed in now when its own request is the late one.
- **The record id is one path segment** `record-id-segment` (`@venizia/ardor-admin`, `@venizia/ardor`): `getOne`, `update` and `delete` percent-encode the id, so `a/b` stays one segment and an id cannot change the path. An empty id, `.`, `..` and a lone surrogate are rejected before any request, and they passed before. A server must decode path parameters, and a record with such an id needs another id.
- **Requests cannot leave the base URL** `request-path-guard` (`@venizia/ardor-kernel`, `@venizia/ardor`): a `paths` entry with a tab, a line break, a backslash or a `.` or `..` segment, or a request that resolves to another origin or outside the base path, rejects with `[doRequest] Invalid path to send request!` before any request.
- **The codemod never writes through a symlink** `codemod-symlink` (`@venizia/ardor`): symlinks are skipped, so `--write` cannot change a file outside the project.
- **The generated app sends a report-only CSP and checks container input** `preset-hardening` (`@venizia/ardor`): new apps send `Content-Security-Policy-Report-Only`, hide the nginx version, refuse more secret-looking `VITE_` variables and validate `NGINX_LOCAL_RESOLVERS`. Apps already generated keep their files.
- **Signing out of an app with no id keeps other sessions** `unscoped-sign-out-keeps-scoped-sessions` (`@venizia/ardor-kernel`, `@venizia/ardor`): signing out of an app with no `id` no longer removes the sessions of apps with an `id` on the same origin. Its store data under `@app/store/` is still removed along with theirs, so give every app on one origin an `id`.
- **The cache is cleared when another user signs in** `cache-cleared-on-user-switch` (`@venizia/ardor-admin`, `@venizia/ardor`): the query cache of `ArdorApplication` is also cleared when another user signs in over the first, with or without a sign-out in between, so the data and the `canAccess` answers of the previous user no longer outlive them. The cache is reset, not just emptied, so a page that is open drops the old data and loads it again for the user signed in now. A token refresh of the same user keeps the cache.
- **The session follows the other tabs** `session-follows-other-tabs` (`@venizia/ardor-kernel`, `@venizia/ardor-admin`, `@venizia/ardor`): a sign-in, sign-out or user switch in one tab now reaches the other tabs of the same app. Their session hooks run, their query cache is reset, and the `@app/store/` data of the ended session is removed there too, in `localStorage` and `sessionStorage`. When another user signs in over the first without a sign-out, the first session ends first (`onSessionCleared` with the reason `external`) and its stored data is removed: in the tab that signed in, in `localStorage` and `sessionStorage`; in a tab that only heard it, in its own `sessionStorage` only, because the other tab already cleared `localStorage` and the new user has written to it since. `DefaultAuthService.subscribe` listeners are told `{ isExternal }`. A tab acts on the change of the token key only: `saveAuth` writes the token last and `cleanUp` removes it first, so the session is whole when the tab hears it. Before, a tab kept showing the old user while its requests already carried the new token.
