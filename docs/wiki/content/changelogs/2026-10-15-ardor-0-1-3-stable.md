# Changelog - 2026-10-15

## ARDOR 0.1.3, stable on the IGNIS 0.2.2 line

<Badge type="tip" text="Enhancement" />

**In one line.** `npm install @venizia/ardor` now installs `0.1.3`: the `0.1.3-0` prerelease moves to `latest` with no code change, and it needs IGNIS `0.2.2`.

## What changed

| Package | `next` | `latest` |
|---|---|---|
| `@venizia/ardor-kernel` | 0.1.3-0 | 0.1.3 |
| `@venizia/ardor-react` | 0.1.3-0 | 0.1.3 |
| `@venizia/ardor-admin` | 0.1.3-0 | 0.1.3 |
| `@venizia/ardor` | 0.1.3-0 | 0.1.3 |

The code is the code of `0.1.3-0`. It carries two changes:

- **IGNIS 0.2.2.** Every IGNIS peer starts at the newest published version: `@venizia/ignis-inversion` and `@venizia/ignis-filter` at `>=0.2.2-0 <0.3.0`, `@venizia/ignis-kernel`, `@venizia/ignis-helpers` and `@venizia/ignis-connectors` at `>=0.2.2-1 <0.3.0`. IGNIS `0.2.1` no longer satisfies them.
- **`canAccess` for every `AuthProvider` subclass.** See [canAccess reaches an AuthProvider subclass without a fourth super argument](./2026-10-14-permission-provider-from-the-container).

## Who is affected

- **Every application.** Move IGNIS together with ARDOR. IGNIS `latest` is still `0.2.1`, so pin the 0.2.2 prereleases explicitly, or let the package manager install them as peers: a fresh `bun add @venizia/ardor` resolves `ignis-inversion` and `ignis-filter` `0.2.2-0`, `ignis-kernel` and `ignis-helpers` `0.2.2-1`.
- **Tests that type an object literal as `ApplicationError`.** IGNIS inversion `0.2.2-0` adds `toFilledText()` to `ApplicationError`, so such a literal no longer compiles. Build the error with `getError(...)`.
- **Applications on `0.1.3-0`.** Move to `0.1.3` when convenient; nothing else changes.
