highlights:
  - 'Binding keys carry the type of their value, and the injectable augmentation interfaces are gone'
  - '`ResponseReader` is `NetworkResponseReader`, and the request class is `NativeFetchNetworkRequest`'
  - 'IGNIS refuses a request path that leaves the base, with a new message'
  - 'The four packages need the IGNIS 0.5 line'
---
ARDOR 0.5.0 follows IGNIS 0.5.0, so the four packages now need the IGNIS 0.5 packages. The biggest change: every key of `CoreBindings`, and every key you write, is made by `BindingKeys.build<T>` and carries the type of its value. That means `useInjectable({ key })` gives you that type back, with no generic and no augmentation. The request class and the response reader have new names, and a few small helpers were removed or renamed. Several changes break existing code. Each entry below says what to change.

## Breaking
- **The keys of CoreBindings carry their value types** `typed-core-bindings` (`@venizia/ardor-kernel`, `@venizia/ardor-admin`, `@venizia/ardor`): Reading a `CoreBindings` key now gives you the real type: `container.get({ key: CoreBindings.APPLICATION_INFO })` is an `IApplicationInfo`. Binding a value of another type under a `CoreBindings` key no longer compiles. Four of the values live in `@venizia/ardor-admin` (the three default providers and the i18n options). They are typed through `ICoreBindingTypes`, which that package merges into, so an app that imports `@venizia/ardor` or `@venizia/ardor-admin` sees the real types. If a test binds a partial fake, make an untyped key from the constant: `BindingKeys.build<unknown>({ key: CoreBindings.X })`.
- **The injectable hooks take a typed key** `typed-injectable-keys` (`@venizia/ardor-react`, `@venizia/ardor-admin`, `@venizia/ardor`): `useInjectable`, `useProvider` and the other namespace hooks now take `{ key: TBindingKey<T> }` and return `T`, so there is no module augmentation to write. `IUseInjectableKeyTypes`, `IUseInjectableKeysOverrides`, `TUseInjectableKeys` and `TUseInjectableKeysDefault` are removed. Delete each `declare module` block that adds an injectable key, and make the key with `BindingKeys.build<T>` instead. `IUseTranslateKeysOverrides` is unchanged.
- **A binding key is made by BindingKeys.build and nothing else** `built-keys-only` (`@venizia/ardor-kernel`, `@venizia/ardor`): `bind`, `get`, `isBound`, `getBinding`, `@inject({ key })` and `@provide({ key })` accept only a key made by `BindingKeys.build<T>`. A plain string, a template literal or a symbol stops compiling. The key strings themselves do not change. Run `bun run devz codemod binding-keys`: it rewrites each literal key and lists the ones it left as `build<unknown>`.
- **ResponseReader is NetworkResponseReader** `network-response-reader-rename` (`@venizia/ardor-kernel`, `@venizia/ardor`): The class behaves the same, but it has a new name and there is no alias. It no longer shares a name with the `ResponseReader` of `@venizia/ignis-helpers`. Rename it by hand; there is no codemod.
- **The request class is NativeFetchNetworkRequest** `native-fetch-network-request` (`@venizia/ardor-kernel`): `DefaultNetworkRequestService` now sends through the IGNIS `NativeFetchNetworkRequest`. If your service subclass assigns the protected `networkRequest`, use the new class. `doRequest` still accepts every status and reads a 4xx or 5xx itself, and a call that carries headers still sends those alone.
- **A path that leaves the base is refused with a new message** `request-path-refusal` (`@venizia/ardor-kernel`): IGNIS now refuses a request path that leaves the base URL, and ARDOR's own check is removed. The status is still 400, but the text changed. It now starts with `[<client name>] ` and reads `A request path must stay under the base path`, followed by the reason, where it used to be `[doRequest] Invalid path to send request!`. If you match on that text, update it. A relative base URL needs a page or worker location, and a base URL that carries a `?` or a `#` is refused. Both answer a 500.
- **The auth hook of the data source is told the attempt** `data-source-auth-attempt` (`@venizia/ardor-kernel`): `getDataSourceAuth().onUnauthorized` takes `(context, { attempt })`, as the IGNIS `HttpDataSource` calls it. On `attempt` 2, the retry's own 401, it never refreshes again and the 401 stands. If a test or a subclass calls the hook, pass `{ attempt: 1 }`.
- **Five connectors HTTP types are removed** `connectors-http-types-removed` (`@venizia/ardor-kernel`, `@venizia/ardor`): `THttpQuery`, `TAuthTokenResolver`, `THttpHeadersResolver`, `HttpResourceEntity` and `THttpRepositoryOptions` are no longer in `@venizia/ardor/repository`, because IGNIS removed them from `@venizia/ignis-connectors/http`. If you imported one, write the type yourself. `THttpFetch` stays.
- **The IGNIS peers are 0.5** `ignis-0-5-peers` (`@venizia/ardor-kernel`, `@venizia/ardor-react`, `@venizia/ardor-admin`, `@venizia/ardor`): The four packages now ask for the IGNIS 0.5 line, so upgrade your IGNIS packages too. They declare `^0.5.0` peers on the IGNIS packages (while IGNIS 0.5.0 is a prerelease the ranges are `^0.5.0-4` for `@venizia/ignis-connectors`, `^0.5.0-3` for `@venizia/ignis-kernel`, `^0.5.0-2` for `@venizia/ignis-helpers` and `@venizia/ignis-boot`, and `^0.5.0-1` for the other IGNIS packages). The app preset needs `@venizia/dev-configs` `^0.5.0`.
- **HttpResponseReader, THttpHeaders and HttpWireHeaders leave `@venizia/ardor/repository`** `ignis-http-readers-moved` (`@venizia/ardor-kernel`, `@venizia/ardor`): The `@venizia/ardor/repository` entry re-exports `@venizia/ignis-connectors/http`, and IGNIS 0.5 no longer exports these three from there. Import `HttpResponseReader` and `THttpHeaders` from `@venizia/ignis-helpers/core`. `HttpWireHeaders` is gone; use `HttpHeaders`, which is also in `@venizia/ignis-helpers/core`. One pairing to avoid: ARDOR 0.5.0-2 must not be used with `@venizia/ignis-kernel` 0.5.0-2 or later, because it imported `HttpResponseReader` from the kernel, where it no longer is. Use ARDOR 0.5.0-3 or later with IGNIS kernel 0.5.0-2.
- **HeaderConstants is gone, use HTTP.Headers** `header-constants-removed` (`@venizia/ardor-kernel`, `@venizia/ardor`): The header names now come from IGNIS's `HTTP.Headers` in `@venizia/ignis-helpers/common`. The names are the same, except `X_AUTH_PROVIDER` is `AUTH_PROVIDER` and `X_LOCALE` is `LOCALE`. The two regular expressions (`TEXTUAL_CONTENT_TYPE_RE`, `ATTACHMENT_CONTENT_DISPOSITION_RE`) have no replacement: nothing outside the response reader used them, so write your own if you did. `ardor codemod namespace` lists each import of `HeaderConstants`.
- **NetworkHeaders is gone, use HttpHeaders** `network-headers-removed` (`@venizia/ardor-kernel`, `@venizia/ardor`): Where you used `NetworkHeaders.merge({ sources })`, use IGNIS's `HttpHeaders.merge({ layers })` from `@venizia/ignis-helpers/core`; where you used `toRecord`, use `Object.fromEntries(new Headers(headers))`. `HttpHeaders.merge` answers a `Headers` object (`Object.fromEntries` turns that into a record), and it removes a header whose value is `null`. The protected `headers` of `DefaultNetworkRequestService` is a `Headers` object now, not a record, so a subclass that read it as a record should read it with `.get(name)`. `setHeaders` and `removeHeaders` work as before, except that they throw on a name that is not a valid header name (a `Headers` object refuses it). `ardor codemod namespace` lists each import of `NetworkHeaders`.
- **Authentication is gone, App.TOKEN_TYPE is the default scheme** `authentication-removed` (`@venizia/ardor-kernel`, `@venizia/ardor`): Nothing in ARDOR used the `Authentication` constants (`TYPE_BASIC`, `TYPE_BEARER`, `STRATEGY_BASIC`, `STRATEGY_JWT`), so they are removed. The places that wrote `'Bearer'` by hand now read `App.TOKEN_TYPE`, the scheme a token gets when it names none. If you used the constants, write the scheme you need as a string. `ardor codemod namespace` lists each import of `Authentication`.
- **NetworkResponseReader.toError is gone, use HttpResponseReader.toApplicationError** `to-error-removed` (`@venizia/ardor-kernel`, `@venizia/ardor`): `toError({ response })` only called IGNIS's `HttpResponseReader.toApplicationError` with the root key `'error'`, so call that yourself: `HttpResponseReader.toApplicationError({ response, rootKey: NetworkResponseReader.ERROR_ROOT_KEY })` from `@venizia/ignis-helpers/core`. The error you get is the same, with the server's own text as `message`. `ardor codemod namespace` lists each use.
- **AuthRecovery is AuthRecoveryHelper** `auth-recovery-helper` (`@venizia/ardor-kernel`, `@venizia/ardor`): The class that shares one token refresh per session is a helper, so it is named like one and extends IGNIS's `BaseHelper`. It no longer takes a `logger` option: it logs under its own name. `DefaultNetworkRequestService` builds it for you, so only code that built one itself has to change. `ardor codemod namespace` lists each import of `AuthRecovery`.
- **ValueUtility drops isObject and isValidDate** `value-utility-trim` (`@venizia/ardor-kernel`, `@venizia/ardor`): Nothing in ARDOR or its examples used these two, so they are removed. `isDefined`, `isString` and `isNumber` stay. Where you need them, use `typeof value === 'object' && value !== null && !Array.isArray(value)` and `!Number.isNaN(new Date(value).valueOf())`.
- **useInjectable takes no generic on options of either shape** `use-injectable-no-claim` (`@venizia/ardor-react`, `@venizia/ardor`): If a variable is typed as both `{ target }` and `{ key }`, `useInjectable` now returns `unknown`, so `useInjectable<Foo>(opts)` no longer compiles. This stops anyone claiming a type that nothing checks. Pass `{ target }` (the class gives the type) or a key made by `BindingKeys.build<T>` (the key gives it), or narrow the value after the call.

## Added
- **FileUtility.save** `file-utility-save` (`@venizia/ardor-kernel`, `@venizia/ardor`): `FileUtility.save({ blob, filename })` makes the browser download a blob as a file, so your app no longer has to write the object URL and the anchor click itself. A missing or empty `filename` saves the file as `download`. It works in a browser only, and throws when there is no `document`.
- **useBreakpoint** `use-breakpoint` (`@venizia/ardor-react`, `@venizia/ardor`): `useBreakpoint()` returns `{ name, isAtLeast(name), isBelow(name) }` for the current breakpoint. It uses a table of named widths that follows Tailwind by default (`sm` 640, `md` 768, `lg` 1024, `xl` 1280, `2xl` 1536). `useBreakpoint({ breakpoints: { compact: 600, wide: 1200 } })` replaces the table with your own and types the names, so `isAtLeast('xxl')` on an unknown name does not compile. `name` is `null` below the smallest breakpoint and in a server render. It reads the viewport through media queries, so browser zoom moves it with the layout, and it re-renders only when the name changes. It is also available as `Ardor.useBreakpoint`.

## Changed
- **Supported runtime: Bun 1.4 or newer** `bun-runtime` (`@venizia/ardor-kernel`, `@venizia/ardor-react`, `@venizia/ardor-admin`, `@venizia/ardor`): The packages declare `engines.bun: >=1.4`. We recommend Bun 1.4.5, a security release with TLS, HTTP and DNS fixes in fetch and node:tls/https/http/dns. It is not required.
- **A file name that cannot be decoded is dropped** `filename-bad-escape` (`@venizia/ardor-kernel`, `@venizia/ardor`): `NetworkResponseReader.readFilename` and the `filename` of `read` now come from IGNIS's `HttpResponseReader.parseContentDisposition`. A `filename*=UTF-8''100%.txt` with a bad percent escape used to give back its raw text (`100%.txt`). Now you get the plain `filename=` of the header, or no name. Every other form (`filename*` decoded, quoted, bare) gives what it gave before. If you call `NetworkResponseReader.read` directly with a response that is not 2xx, it now throws an `ApplicationError` when it reads a file (IGNIS `readFile` refuses it). `doRequest` checks the status first, so it is not affected.

## Fixed
- **The retry after a 401 sends the same headers and body type as the first send** `retry-keeps-headers` (`@venizia/ardor-kernel`, `@venizia/ardor`): A `doRequest` with no headers, retried after a token refresh, kept only the auth header. The headers set with `setHeaders` were lost, and a JSON body went out as `text/plain`. The retry now sends the current service headers and the same content type as the first send. The provider of the fresh token (or none) replaces the `x-auth-provider` the call carried. A `ReadableStream` body cannot be sent a second time: after the refresh the call throws an error that says so and sends nothing, where the second send used to fail with an unclear `TypeError` (body disturbed). `FormData`, `Blob` and string bodies are sent again.
- **A denied user no longer triggers the record request, or lands on the list** `denied-show-no-fetch` (`@venizia/ardor-admin`, `@venizia/ardor`): react-admin sends `getOne` for a show or edit page as soon as the access check is done, even when access is denied. So a user who was being sent to `/access-denied` could end up on the list with a "does not exist" notice if that request failed at once. `ArdorApplication` now mounts the `show` and `edit` pages of each resource behind their own access check. A denied user sends no request and always reaches the access-denied page.
