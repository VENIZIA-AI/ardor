ARDOR 0.5.0 follows IGNIS 0.5.0. Every key of `CoreBindings`, and every key you write, is made by `BindingKeys.build<T>` and carries the type of its value, so `useInjectable({ key })` answers that type with no generic and no augmentation. The request class and the response reader have new names, and the packages need the IGNIS 0.5 line. Several changes are breaking, and each entry says what to change.

## Breaking
- **The keys of CoreBindings carry their value types** `typed-core-bindings` (`@venizia/ardor-kernel`, `@venizia/ardor-admin`, `@venizia/ardor`): `container.get({ key: CoreBindings.APPLICATION_INFO })` is an `IApplicationInfo`, and binding a value of another type under a `CoreBindings` key does not compile. The four values that live in `@venizia/ardor-admin` (the three default providers and the i18n options) are typed through `ICoreBindingTypes`, which that package merges into, so an app that imports `@venizia/ardor` or `@venizia/ardor-admin` reads the real types. A test that binds a partial fake makes an untyped key from the constant with `BindingKeys.build<unknown>({ key: CoreBindings.X })`.
- **The injectable hooks take a typed key** `typed-injectable-keys` (`@venizia/ardor-react`, `@venizia/ardor-admin`, `@venizia/ardor`): `useInjectable`, `useProvider` and the other namespace hooks take `{ key: TBindingKey<T> }` and return `T`. `IUseInjectableKeyTypes`, `IUseInjectableKeysOverrides`, `TUseInjectableKeys` and `TUseInjectableKeysDefault` are removed, so delete each `declare module` block that adds an injectable key and make the key with `BindingKeys.build<T>`. `IUseTranslateKeysOverrides` is unchanged.
- **A binding key is made by BindingKeys.build and nothing else** `built-keys-only` (`@venizia/ardor-kernel`, `@venizia/ardor`): `bind`, `get`, `isBound`, `getBinding`, `@inject({ key })` and `@provide({ key })` take only a key made by `BindingKeys.build<T>`; a plain string, a template literal or a symbol stops compiling. The key strings do not change. `bun run devz codemod binding-keys` rewrites each literal key and lists the ones it left as `build<unknown>`.
- **ResponseReader is NetworkResponseReader** `network-response-reader-rename` (`@venizia/ardor-kernel`, `@venizia/ardor`): same behaviour, new name, no alias, so it no longer shares a name with the `ResponseReader` of `@venizia/ignis-helpers`. Rename it by hand; there is no codemod.
- **The request class is NativeFetchNetworkRequest** `native-fetch-network-request` (`@venizia/ardor-kernel`): `DefaultNetworkRequestService` sends through the IGNIS `NativeFetchNetworkRequest`, and a service subclass that assigns the protected `networkRequest` uses the new class. `doRequest` accepts every status and still reads a 4xx or 5xx itself, and a call that carries headers still sends those alone.
- **A path that leaves the base is refused with a new message** `request-path-refusal` (`@venizia/ardor-kernel`): ARDOR's own check is removed and IGNIS refuses the path. The status is still 400, and the text is `A request path must stay under the base path`, where it was `[doRequest] Invalid path to send request!`. A relative base URL needs a page or worker location, and a base URL that carries a `?` or a `#` is refused; both answer a 500.
- **The auth hook of the data source is told the attempt** `data-source-auth-attempt` (`@venizia/ardor-kernel`): `getDataSourceAuth().onUnauthorized` takes `(context, { attempt })`, as the IGNIS `HttpDataSource` calls it. On `attempt` 2, the retry's own 401, it never refreshes again and the 401 stands. A test or a subclass that calls the hook passes `{ attempt: 1 }`.
- **Five connectors HTTP types are removed** `connectors-http-types-removed` (`@venizia/ardor-kernel`, `@venizia/ardor`): `THttpQuery`, `TAuthTokenResolver`, `THttpHeadersResolver`, `HttpResourceEntity` and `THttpRepositoryOptions` are gone from `@venizia/ardor/repository`, as IGNIS removed them from `@venizia/ignis-connectors/http`. `THttpFetch` stays.
- **The IGNIS peers are 0.5** `ignis-0-5-peers` (`@venizia/ardor-kernel`, `@venizia/ardor-react`, `@venizia/ardor-admin`, `@venizia/ardor`): the packages declare `^0.5.0` peers on the IGNIS packages (`^0.5.0-3` for `@venizia/ignis-connectors`, `^0.5.0-2` for `@venizia/ignis-kernel` and `^0.5.0-1` for `@venizia/ignis-helpers` and `@venizia/ignis-boot` while IGNIS 0.5.0 is a prerelease), and the app preset needs `@venizia/dev-configs` `^0.5.0`.
- **HttpResponseReader, THttpHeaders and HttpWireHeaders leave `@venizia/ardor/repository`** `ignis-http-readers-moved` (`@venizia/ardor-kernel`, `@venizia/ardor`): the sub-path re-exports `@venizia/ignis-connectors/http`, and IGNIS 0.5 no longer exports these three from it. `HttpResponseReader` and `THttpHeaders` are in `@venizia/ignis-helpers/core`; `HttpWireHeaders` is gone, and `HttpHeaders` (also in `@venizia/ignis-helpers/core`) replaces it. ARDOR 0.5.0-2 must not be paired with `@venizia/ignis-kernel` 0.5.0-2 or later: it imported `HttpResponseReader` from the kernel, where it no longer is. Use ARDOR 0.5.0-3 or later with IGNIS kernel 0.5.0-2.
- **HeaderConstants is gone, use HTTP.Headers** `header-constants-removed` (`@venizia/ardor-kernel`, `@venizia/ardor`): the header names are IGNIS's `HTTP.Headers` from `@venizia/ignis-helpers/common`. The names are the same, except `X_AUTH_PROVIDER` is `AUTH_PROVIDER` and `X_LOCALE` is `LOCALE`. The two regular expressions (`TEXTUAL_CONTENT_TYPE_RE`, `ATTACHMENT_CONTENT_DISPOSITION_RE`) have no replacement: nothing outside the response reader used them. `ardor codemod namespace` lists each import of `HeaderConstants`.
- **NetworkHeaders is gone, use HttpHeaders** `network-headers-removed` (`@venizia/ardor-kernel`, `@venizia/ardor`): `NetworkHeaders.merge({ sources })` and `toRecord` are IGNIS's `HttpHeaders.merge({ layers })` from `@venizia/ignis-helpers/core`, which answers a `Headers` object (`Object.fromEntries` makes a record) and removes a header whose value is `null`. `DefaultNetworkRequestService`'s protected `headers` is a `Headers` object now, not a record, so a subclass that read it as a record reads it with `.get(name)`. `setHeaders` and `removeHeaders` are unchanged. `ardor codemod namespace` lists each import of `NetworkHeaders`.

## Added
- **useBreakpoint** `use-breakpoint` (`@venizia/ardor-react`, `@venizia/ardor`): `useBreakpoint()` returns `{ name, isAtLeast(name), isBelow(name) }` for the current breakpoint, from a table of named widths that follows Tailwind by default (`sm` 640, `md` 768, `lg` 1024, `xl` 1280, `2xl` 1536). `useBreakpoint({ breakpoints: { compact: 600, wide: 1200 } })` replaces the table and types the names, so `isAtLeast('xxl')` on an unknown name does not compile. `name` is `null` below the smallest breakpoint and in a server render. It reads the viewport through media queries, so browser zoom moves it with the layout, and it re-renders only when the name changes. It is also `Ardor.useBreakpoint`.

## Changed
- **Supported runtime: Bun 1.4 or newer** `bun-runtime` (`@venizia/ardor-kernel`, `@venizia/ardor-react`, `@venizia/ardor-admin`, `@venizia/ardor`): the packages declare `engines.bun: >=1.4`. Bun 1.4.5 is recommended: it is a security release with TLS, HTTP and DNS fixes in fetch and node:tls/https/http/dns. It is not required.
- **useInjectable takes no generic on options of either shape** `use-injectable-no-claim` (`@venizia/ardor-react`, `@venizia/ardor`): a variable typed as both `{ target }` and `{ key }` now returns `unknown`, so `useInjectable<Foo>(opts)` no longer compiles and nobody can claim a type nothing checks. Pass `{ target }` (the class gives the type) or a key made by `BindingKeys.build<T>` (the key gives it), or narrow the value after the call.

## Fixed
- **The retry after a 401 sends the same headers and body type as the first send** `retry-keeps-headers` (`@venizia/ardor-kernel`, `@venizia/ardor`): a `doRequest` with no headers, retried after a token refresh, kept only the auth header, so the headers set with `setHeaders` were dropped and a JSON body went out as `text/plain`. The retry now sends the current service headers and the same content type as the first send, and the provider of the fresh token (or none) replaces the `x-auth-provider` the call carried. A `ReadableStream` body cannot be sent a second time: after the refresh the call throws an error that says so and sends nothing, where the second send failed with an unclear `TypeError` (body disturbed). `FormData`, `Blob` and string bodies are sent again.
- **A denied user no longer triggers the record request, or lands on the list** `denied-show-no-fetch` (`@venizia/ardor-admin`, `@venizia/ardor`): react-admin sends `getOne` for a show or edit page as soon as the access check is done, a denial included, so a user it was sending to `/access-denied` could instead land on the list with a "does not exist" notice when the request failed at once. `ArdorApplication` now mounts the `show` and `edit` pages of each resource behind their own access check, so a denied user sends no request and always reaches the access-denied page.
