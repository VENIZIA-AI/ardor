ARDOR 0.4.7 moves utility functions onto classes and removes the old bare names, replaces the kernel logger with the one from IGNIS, and adds the `Ardor` hook namespace and a codemod that updates your code. It also adds lazy i18n sources, session hooks on `DefaultAuthProvider`, typed browser storage, `useStoredState`, `useElementSize` and a typed request body. An app on 0.4.6 that uses a renamed, moved or removed name does not compile until it runs the codemod and fixes by hand what the codemod only lists.

## Breaking

- **Utility functions and factories are class members** `class-namespace-functions` (`@venizia/ardor-kernel`, `@venizia/ardor-react`, `@venizia/ardor-admin`, `@venizia/ardor`): `isDefined`, `isString`, `isNumber`, `isObject`, `isValidDate`, `isBrowser`, `toDataUrl`, `getRuntimeConfig`, `createAppDispatch`, `createAppSelectors`, `resolveApplicationProviders`, `hasPendingFeatureMessages` and `loadFeatureMessages` are gone. Use `ValueUtility`, `BrowserUtility`, `FileUtility`, `RuntimeConfig.get`, `DispatchHooks.create`, `SelectorHooks.create`, `ApplicationProviders.resolve`, `Features.hasPendingMessages` and `Features.loadMessages`. Run `bun run ardor codemod namespace`.
- **Three id and nullable types are plain types** `plain-id-types` (`@venizia/ardor-kernel`, `@venizia/ardor`): `NumberIdType`, `StringIdType` and `NullableType` are removed. Write `number`, `string` and `undefined | null | void`. The codemod does it.
- **Unused exports are removed** `removed-unused-exports` (`@venizia/ardor-kernel`, `@venizia/ardor-react`, `@venizia/ardor`): `isEditableTarget`, `TDataCount`, `ISyncFC`, `App.DEFAULT_LOCALE`, `HeaderConstants.REQUEST_DEVICE_INFO` and `HeaderConstants.RESPONSE_FORMAT`. ARDOR never used them. The codemod lists each import of them, and each use of the `App` and `HeaderConstants` members, for you to replace by hand.
- **The logger is IGNIS's `ILogger`, and `enableDebug` is gone** `ignis-logger` (`@venizia/ardor-kernel`, `@venizia/ardor-react`, `@venizia/ardor-admin`, `@venizia/ardor`): `Logger`, `LogLevels`, `ILogger`, `TLogLevel` and `BaseHelper` are removed from the kernel; import `LogLevels`, `ILogger`, `TLogLevel` and `BaseHelper` from `@venizia/ignis-helpers/core`, and use `LoggerFactory.getLogger([scope])` instead of `Logger.getInstance`. `<ArdorApplication enableDebug />` becomes `<ArdorApplication logger={...} />`. A class that `implements ILogger` must add `emerg`, `log` and `for`. Log calls take a format string first. `AuthRecovery` and `IApplicationContextValue.logger` take the IGNIS `ILogger`. Debug lines are off by default: set `LoggerFactory.use({ level })` once at start if you want them.
- **Sign-out clears only `@app/auth/`** `sign-out-oauth2-prefix` (`@venizia/ardor-kernel`, `@venizia/ardor-admin`, `@venizia/ardor`): `DefaultAuthService.cleanUp` no longer removes keys under `@app/oauth2/`, and `LocalStorageKeys.PREFIX_OAUTH2` is removed. If you keep OAuth2 state there, remove it yourself on sign-out.
- **IGNIS peer versions are higher** `ignis-peer-floors` (`@venizia/ardor-kernel`, `@venizia/ardor-react`, `@venizia/ardor-admin`, `@venizia/ardor`): `@venizia/ignis-helpers`, `-kernel`, `-boot` and `-connectors` need `^0.4.7`, and `-inversion` and `-filter` need `^0.4.6`. Move all your `@venizia/ignis-*` packages to the IGNIS 0.4.7 release.

## Added

- **The `Ardor` hook namespace** `ardor-namespace` (`@venizia/ardor`): `Ardor.useRepository()`, `Ardor.useTranslate()` and the other hooks of the react and admin packages (25 in all) are the same functions as the standalone hooks. The standalone hooks stay exported.
- **The `ardor` codemod command** `ardor-codemod` (`@venizia/ardor`): `bun run ardor codemod namespace [paths] [--write] [--allow-dirty] [--check] [--hooks]` updates the renames above, moves the kernel logger to IGNIS's, and lists what it cannot change. `--hooks` also moves hooks to `Ardor.useX`. It reads `.ts`, `.tsx`, `.mts` and `.cts` files and needs `typescript` (`>=5.0.0`, an optional peer).
- **Lazy i18n sources** `lazy-i18n-sources` (`@venizia/ardor-admin`, `@venizia/ardor`): an entry of `i18nSources` can be `() => import('./vi')`, called the first time its locale is used, so a catalogue stays out of the boot bundle. A loader that fails leaves the locale on English and is tried again on the next `changeLocale()`. `TI18nSource` is the new type. A subclass of `DefaultI18nProvider` that overrides `composeMessages` must read a locale through `this.localeSources.readNow({ locale })`.
- **Session hooks on `DefaultAuthProvider`** `session-hooks` (`@venizia/ardor-admin`, `@venizia/ardor`): override `onSessionStarted({ token, user })` and `onSessionCleared({ reason })` to keep a socket or a per-user cache in step with the session, instead of overriding `checkAuth`, `logout` or `saveSession`. They run once per change of the session, are awaited, and cannot break sign-in when they throw. `sessionHookTimeout` (10 seconds) bounds a hook; do not call `this.logout()` from a hook. New exports: `SessionClearReasons` and `TSessionClearReason`.
- **The session hooks see every token change** `session-token-changes` (`@venizia/ardor-kernel`, `@venizia/ardor-admin`, `@venizia/ardor`): `DefaultAuthService.subscribe({ listener })` runs after each `saveAuth` and `cleanUp`, so `onSessionStarted` also fires for a token your network service refreshes, and `onSessionCleared` fires with the reason `external` for a `cleanUp` made elsewhere. The provider listens from its constructor: build one per auth service and call `dispose()` on one you discard.
- **A configurable rejection for guest apps** `unauthenticated-rejection` (`@venizia/ardor-admin`, `@venizia/ardor`): override `unauthenticatedRejection({ reason })` to set what `checkAuth` and a 401 reject with. `{ logoutUser: false }` keeps the stored session on a 401, so clear or replace a revoked token yourself. `IAuthRejection` is the new type. The default is the old redirect to the login page.
- **Typed browser storage** `browser-storage` (`@venizia/ardor-kernel`, `@venizia/ardor`): `BrowserStorage` has `get`, `set`, `remove` and `subscribe` over `localStorage` and `sessionStorage` (`StorageAreas`), with an optional codec (`IStorageCodec`). It never throws: a blocked or full storage gives the fallback or `false`. It refuses to write or remove keys under `@app/auth/`. `TStorageArea` is the type of an area name. `LocalStorageKeys.PREFIX_STORE` is `@app/store/`, the suggested key prefix for your own keys.
- **`useStoredState`** `use-stored-state` (`@venizia/ardor-react`, `@venizia/ardor`): `useStoredState({ key, defaultValue, storage?, codec? })` returns `{ value, setValue, remove }` and keeps hooks, `BrowserStorage` writes and other tabs in step.
- **`useElementSize`** `use-element-size` (`@venizia/ardor-react`, `@venizia/ardor`): measures an element with a `ResizeObserver`, one update per animation frame. Pass a stable `ref`, or pass none and give the returned `ref` to the element so it follows one that mounts later. `box` picks the content or border box, `round` rounds to whole pixels, and `measured` tells a measured 0 by 0 from one not read yet. On a host with no `ResizeObserver` it stays at 0 by 0 and does not throw.
- **`FakeResizeObserver` for tests** `fake-resize-observer` (`@venizia/ardor`): from `@venizia/ardor/testing`. `FakeResizeObserver.install()` puts a fake on `globalThis.ResizeObserver` and returns a function that restores the old one; `FakeResizeObserver.flush({ element, width, height })` delivers a size.
- **A typed request body** `typed-request-body` (`@venizia/ardor-kernel`, `@venizia/ardor`): `RequestBodyEncoder.encode` answers `{ body, contentType }` and the type of `body` now follows `bodyType`: a `FormData` for `form-data`, a `URLSearchParams` for `x-www-form-urlencoded`, and the body you passed for `json`, `none` or `binary`. Nothing changes at run time.
- **`ResponseReader.readFilename`** `read-filename` (`@venizia/ardor-kernel`, `@venizia/ardor`): `ResponseReader.readFilename({ headers })` returns the file name in `Content-Disposition` (`filename*` before `filename`), or `undefined`.

## Changed

- **`assertArdorApplicationBoots` needs a newer inversion** `assert-boots-inversion` (`@venizia/ardor`): it calls `BindingVerifier.assertResolve` of `@venizia/ignis-inversion`, which exists from `0.4.6-1`. An older copy fails at once with a message naming the version. The peer range already asks for `^0.4.6`.
- **`buildInfoFile` no longer installs a quiet logger** `build-info-quiet-logger` (`@venizia/ardor`): `buildInfoFile` of `@venizia/ardor/vite` leaves the IGNIS default logger in place; its "git unavailable" lines are debug lines and print only when `DEBUG` is set.
- **`AuthTokenStore` logs through IGNIS** `auth-token-store-logger` (`@venizia/ardor-kernel`, `@venizia/ardor`): the warning about an unreadable stored token has the same text and payload, in the IGNIS line format (`[scope] message`, no timestamp or level in the text).
