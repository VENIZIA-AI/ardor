# Changelog - 2026-10-12

## ARDOR 0.1.2, stable on IGNIS 0.2.1

<Badge type="tip" text="Enhancement" />

**In one line.** `npm install @venizia/ardor` now installs `0.1.2`: the prereleases verified under `next` move to `latest` with no code change.

## What changed

| Package | `next` | `latest` |
|---|---|---|
| `@venizia/ardor-kernel` | 0.1.2-7 | 0.1.2 |
| `@venizia/ardor-react` | 0.1.2-7 | 0.1.2 |
| `@venizia/ardor-admin` | 0.1.2-10 | 0.1.2 |
| `@venizia/ardor` | 0.1.2-10 | 0.1.2 |

The code is the code of the prereleases; the published tarballs differ only in `package.json` (the version and the internal ranges, now `^0.1.2`). The entries from [2026-10-02](./2026-10-02-repository-writes-and-ignis-0-2-1) to [2026-10-10](./2026-10-10-document-title-cleanup-guard) describe what it contains. Before this, `latest` pointed at `0.1.1`.

## Who is affected

- **Applications on `0.1.1`.** Read the entries from 2026-10-02 on before moving: the 2026-10-02 entry is breaking (`BaseCrudService` is gone), and the 2026-10-09 and 2026-10-10 entries each carry a breaking-changes section.
- **Applications on a `0.1.2-x` prerelease.** Move to `0.1.2` when convenient. From an early prerelease, read the entries published after it: `0.1.2-2` of `@venizia/ardor` predates every entry from 2026-10-06 on.
- **Every application.** The IGNIS peers are unchanged, `>=0.2.1-x <0.3.0`, so the stable IGNIS `0.2.1` satisfies them.
