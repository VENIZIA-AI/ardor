# Knowledge log

One line per change to a fact in this bundle, newest first. A code change that moves a fact lands
with its line here in the same change (rule P-03).

- 2026-09-24 - A DELETE with a body crosses BANA's gateway intact. Measured on Traefik v3.6.25 (BANA develop runs `traefik:v3.6`) with BANA's own `middlewares.yml` and the commerce router's chain (`rate-limit`, `security-headers`, proven active by their response headers): the `deleteMany` body with 2000 UUIDs (78 026 bytes) reached the backend byte for byte, as a PATCH did; a DELETE without a body arrived empty (control). BANA's app `nginx.conf` files serve static files only, so the browser calls the gateway directly. Not measured: the local-dev `nginx.conf` (plain `proxy_pass`, `client_max_body_size 50m`, no nginx on this machine) and any proxy in front of Traefik on develop that is not in the BANA repo.
- 2026-09-24 - ARDOR cut its first stable line: kernel, react, admin and ardor 0.1.1 and ui-kit 0.0.2 on `latest`, the same code as the `next` prereleases; a fresh `bun add @venizia/ardor` resolves only 0.1.1 and IGNIS 0.2.0. Two gaps in `scripts/release.ts` showed up. It verified a publish by reading the `next` dist-tag, so a stable release (published to `latest`) timed out as a false failure after kernel; it now snapshots the registry's version list before dispatch and waits for a new version, whatever its tag. It also decided what needs releasing from `src` changes only, so a manifest-only change (the umbrella's peers) was skipped unless the package was named; `scripts/release-scope.ts` now counts `package.json` and `tsconfig.build.json` too, tested against a real git history.
- 2026-09-24 - IGNIS cut its first stable line, 0.2.0, from the prerelease line ARDOR tested; the published tarballs match kernel 0.2.0-47, connectors 0.2.0-46, helpers 0.2.0-41, inversion 0.2.0-24 and filter 0.2.0-23 file for file (only the version and internal ranges differ). ARDOR's catalog and peers are `^0.2.0`. The peers used to be open-ended `>=0.2.0-4x`, which `Bun.semver` confirms a future 0.3.0 or 1.0.0 would satisfy; `^0.2.0` bounds them to 0.2.x and no longer accepts a prerelease. `dev-configs` moved to its stable `^0.2.0` too.
- 2026-09-24 - IGNIS 0.2.0-50 is the floor (kernel 0.2.0-47, connectors 0.2.0-46; the rest unchanged). It fixes the case below: `@repository` now judges an `@inject({ target })` whose class has no key yet by its class, so a datasource registered by hand mixes with a discovered repository. The `test.failing` in `remote-repository.test.ts` is a plain test that resolves through a started application (red when the by-hand registration is removed), and the workaround warnings are gone from the wiki and the bundle.
- 2026-09-24 - IGNIS 0.2.0-49 is the floor: kernel 0.2.0-46, connectors 0.2.0-45, helpers 0.2.0-41, inversion 0.2.0-24, filter 0.2.0-23, one copy of each in the lock. An `HttpRepository` is declared `@repository({ type: RepositoryTypes.REMOTE, dataSource })` and discovered; `RepositoryTypes` is re-exported from `@venizia/ignis-kernel/repository` (+0.01 kB, kernel 6.55 of 7.7 kB). The decorator injects `datasources.<ClassName>` at constructor parameter 0, but checks an explicit `@inject({ target })` there at decoration, before `bindContext()` records a by-hand datasource's key, so that combination throws; pinned as `test.failing` in `remote-repository.test.ts`. IGNIS confirmed it predates this batch (in every kernel since 0.2.0-0, `persistents.ts` `registerDataSourceInjection`) and put the fix on its decision list: accept the declared datasource class when no key is recorded yet, or check at resolve time. ARDOR could not reach it before, since `@repository` needed a model. `HttpDataSource` takes a relative `baseUrl`, resolved against `location.href` per request, so the `new URL('/api', window.location.origin)` workaround is gone. The quickstart, the README and `examples/5-mins-qs` now use discovery; the example ran in a browser from its minified bundle (classes renamed `zv`/`jv`, 11 expensive of 27). Two stale passages from 09-23 were fixed: application-lifecycle still called `service()` shorthand for `injectable()`, and design-decisions said every path forces singleton.
- 2026-09-23 - Two registration modes, as in IGNIS: discovery by stereotype, and `service()`/`repository()`/`dataSource()`/`component()` by hand (`IArtifactRegistration { binding, scope, allowOverride }`, returning the `Binding`). Every path, `bindingList()` and `injectable()` included, now records the key on the class, so `@inject({ target })` and `use*({ target })` resolve a class registered by hand; the old "only a stereotyped class resolves by target" is gone. Every kind defaults to singleton, and `registerArtifacts()` honours a stereotype's `scope`. `useRepository` is new. `BaseApiService` is deleted: `@api()` works on any `BaseService` and reads an optional `resource`. IGNIS bumped (connectors 0.2.0-44, kernel 0.2.0-45, helpers 0.2.0-40, filter 0.2.0-22, inversion 0.2.0-23), Bun >= 1.4. `make clean-install` packs every package into empty sandboxes and imports each entry with Bun, Node ESM and a browser build; it runs in CI and before every release bump. It found three packaging bugs, all fixed: the umbrella lacked `ignis-connectors` and `socket.io-client` as optional peers, `react-redux` was optional yet statically imported (now required), and extensionless imports broke Node ESM (`tsc-alias resolveFullPaths`, `lodash/x.js`). A lint rule (`scripts/eslint/secure-context.mjs`) bans `randomUUID`. The release commit now carries `bun.lock`.
- 2026-09-19 - `x-request-id` comes from `uuidV4()` in `@venizia/ignis-helpers/uuid`, and `@venizia/ignis-helpers` is a peer of `ardor-kernel`. It used to call `crypto.randomUUID` directly, which is secure-context-only: since every request carries that header, a plain-http origin like `http://<lan-ip>` threw before anything was sent - the whole app, not one call. The local fallback that fixed it is deleted. ARDOR asked IGNIS for a sub-path after measuring `UuidHelper` at 10.2 kB gzip through `./core` (the weight was `getError` plus a status-code table behind one guard in `v5`, never SHA-1); IGNIS split v4/v5/v7 into free functions, and `uuidV4` is 398 B. It is COUNTED in the 7.7 kB budget - not in the size-limit `ignore` list like the other peers - and the kernel still went 6.42 -> 6.33 kB, so the shared helper is smaller than the hand-written fallback was. No gate catches the underlying class: purity checks node builtins, and `randomUUID` exists in Bun and in every browser tab; a lint rule was asked for and refused upstream, so ARDOR would have to write its own.
- 2026-09-18 - ARDOR pins the released IGNIS chain: `connectors@0.2.0-42`, `kernel@0.2.0-43`, `helpers@0.2.0-38`, `filter@0.2.0-21`, `inversion@0.2.0-22`, with peer floors raised to match what is tested - an older floor let a consumer keep a second `inversion` copy once `connectors` pulled its own. The five contract cases ARDOR had pinned as `test.failing` all pass on the release and are plain tests now: `records */N` totals, a configured `x-request-count` refused at construction, a count route answering no number, a list body that is neither an array nor an envelope, and two spellings of one header name no longer joining.
- 2026-09-17 - `updateMany` and `deleteMany` send the selector `where.id = { inq: ids }` in the BODY, one request each. `updateMany` used to send `filter.where` in the query, which an IGNIS bulk route - it reads a top-level `where` - does not recognise, and `deleteMany` fired one DELETE per id, non-atomically. An id list on the request line drew 431 at 400 UUIDs. Needs a server whose bulk routes accept `where` in the body; one that reads only the query answers 400 and writes nothing. Both results are now `{ data: ids }` read from the affected rows the route answers - they used to hand react-admin the raw rows where it expects ids. `getMany` is still a GET with its `inq` in the URL.
- 2026-09-17 - The network service's header record is keyed by lowercase name, and merges REPLACE across case: `X-Request-Count` beside `x-request-count` used to reach the server as `"1, 0"`. `HeaderConsts.TIMEZONE`/`TIMEZONE_OFFSET` are lowercase to match, and `removeHeaders` lowercases the names it is given. `x-auth-provider` is omitted when a token names no provider (it used to send the string `undefined`). The token comes from `setAuthToken`, else the `authTokenResolver` option - default `readAuthTokenFromStorage`, now exported - so `localStorage` is no longer read unconditionally. The HTTP repository is re-exported from `@venizia/ignis-connectors/http` on the `./repository` sub-path, an optional peer; ARDOR's own copy is gone.
